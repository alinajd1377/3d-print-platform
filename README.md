# پرینت‌یار | سامانه سفارش چاپ سه‌بعدی

نسخه توسعه‌ای فارسی و راست‌چین برای سفارش چاپ FDM و رزینی، با Django، PostgreSQL و Next.js.

## اجرای محلی با Docker
1. از فایل `.env.example` یک کپی با نام `.env` بسازید و مقادیر محلی را تنظیم کنید.
2. اجرا:
   ```bash
   docker compose up --build
   ```
3. ساخت مدیر:
   ```bash
   docker compose exec backend python manage.py createsuperuser
   ```
4. پنل مدیریت: `http://localhost:8000/admin/`
5. سایت: `http://localhost:3000/`

در هر بار اجرا فقط migrationهای ثبت‌شده اعمال می‌شوند؛ ساخت migration به‌صورت خودکار در زمان بالا آمدن سرور انجام نمی‌شود.

## تنظیم اولیه از پنل مدیریت
- **Materials**: متریال‌ها را با تکنولوژی FDM یا RESIN و قیمت هر گرم ثبت کنید.
- **Machines**: دستگاه، تعرفه ساعتی، هزینه آماده‌سازی، حجم ساخت X/Y/Z، قطر نازل‌ها (به‌شکل فهرست JSON مثل `[0.4, 0.6]`)، بازه ارتفاع لایه، سرعت و متریال‌های سازگار را تعریف کنید.
- **Print options**: گزینه‌های قابل‌نمایش به مشتری را اضافه کنید. کلیدهای شناخته‌شده در فرم سفارش:
  - `infill` با مقدارهایی مانند `20`, `40`, `60`
  - `layer_height` با مقدارهایی مانند `0.12`, `0.20`, `0.28`
  - `nozzle_diameter` با مقدارهایی مانند `0.25`, `0.40`, `0.60`
  - `color` با مقدارهایی مانند `مشکی`, `سفید`
  - `supports` با مقدارهای `true` و/یا `false`
  فقط گزینه‌های فعال و مربوط به تکنولوژی انتخابی به مشتری نمایش داده می‌شوند.
- **Pricing rules**: قواعد قیمت‌گذاری پایه را تنظیم کنید.

## رفتار انتخاب دستگاه
مشتری تکنولوژی و متریال را انتخاب می‌کند، نه دستگاه فیزیکی. سرور یک دستگاه فعال با تکنولوژی و متریال سازگار را انتخاب می‌کند و تعرفه دستگاه در برآورد قیمت وارد می‌شود. در صورت ثبت حجم ساخت، پس از اتصال تحلیل هندسی باید ابعاد مدل با حجم دستگاه کنترل شوند. اگر هیچ دستگاه سازگاری فعال نباشد، سفارش بدون دستگاه ثبت می‌شود و باید توسط مدیر بررسی شود.

## سابقه و اصلاح سفارش
مدیر می‌تواند فایل، متریال، دستگاه، رنگ، لایه، تراکم، ساپورت، تعداد، وزن/زمان کارشناسی، مبلغ و وضعیت را در پنل سفارش تغییر دهد. در هر ذخیره ویرایش مدیریتی، مقادیر قبل و بعد در `OrderRevision` ثبت می‌شود. دلیل تغییر را در فیلد «دلیل تغییر سفارش» وارد کنید. نسخه‌های تاریخچه در همان صفحه سفارش نمایش داده می‌شوند.

## محدودیت‌های فعلی (شفاف و مهم)
- ورود و ثبت‌نام با شماره موبایل هنوز پیاده‌سازی نشده است؛ API سفارش فعلاً به احراز هویت Django نیاز دارد. رمز عبور کاربران باید فقط با سیستم هش Django ذخیره شود.
- تحلیل ابعاد فایل و اتصال واقعی PrusaSlicer هنوز پیاده‌سازی نشده است. وزن و زمان از فرم مشتری پذیرفته نمی‌شوند و تا اتصال Slicer مقدار معتبر تولیدی ندارند؛ مدیر می‌تواند پس از بررسی مقدار کارشناسی را وارد کند.
- Worker صف پردازش Slicer، اسکن امنیتی فایل‌های آپلودی، تست‌های خودکار، محدودیت نرخ، استقرار HTTPS و تنظیمات تولیدی باقی مانده‌اند.
- پرداخت زرین‌پال در این مرحله عمداً غیرفعال است (`PAYMENTS_ENABLED=0`). آن را فقط در مرحله نهایی، پس از تست کامل پیش‌فاکتور و callback، فعال کنید.
- این بسته برای توسعه محلی است، نه انتشار مستقیم روی سرور عمومی.

## امنیت فایل تنظیمات
فایل `.env` را در اختیار دیگران قرار ندهید و در Git/ZIP عمومی قرار ندهید. برای انتشار واقعی، کلید Django و رمز دیتابیس را با مقادیر تصادفی و قوی جایگزین کنید.
